## The four findings to fix (QA reproduced each against the real `GitPublisher` / `SubprocessPublishGit` on local repos; its scripts are gone, so the Engineer must write the failing tests itself)
All four of 1 need the agent to run code (for example a test executed by `make test`) after its last commit.

1. **Diff-gate bypasses** (`responder/vt_responder/publisher.py`):
   - a. *Symlink swap:* agent commits `.github/workflows/evil.yml`, then swaps the working-tree `.github` for a symlink to `backend`. `check_publish_path` resolves the committed path against the working tree, sees `backend/...`, allows it. Same for `responder/vt_responder/policy.py`. **Fix:** judge the committed path string (from `git diff --name-status` / the tree), never a working-tree `realpath`.
   - b. *Intermediate commits:* the gate checks only the net `git diff base head`. Commit 1 adds `.github/workflows/evil.yml` plus a `leak.txt`, commit 2 removes them, commit 3 is the real fix; all three are pushed with the files in history (same for an executable). **Fix:** check every commit's paths (`git log --name-status base..head`), or push ONE commit the runner builds itself (squash the final tree onto the base). Squashing is simplest and also removes the merge-commit and commit-count cases.
   - c. *`git replace`:* makes the gate's `git diff` show a benign tree while the evil commit is pushed. **Fix:** pass `--no-replace-objects` (or `GIT_NO_REPLACE_OBJECTS=1`) on every runner git call.
   - d. *Global git config:* the runner's push honours the owner's `~/.gitconfig` (`http.sslVerify=false`, `http.proxy`, `url.insteadOf` were all seen). The agent runs with the owner's real `HOME`, so it can write that file. **Fix:** set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1` for every runner git call (the runner's own `-c` options carry what it needs).
2. **CLI allow list permits more than `ToolPolicy`** (`responder/vt_responder/cli_rules.py`, checked with the Engineer's own `cli_rules.evaluate`): `git diff --output=<path>` and `git log --output=<path>` (write outside the checkout; not in the documented limits), `git diff --no-index <file>` (read outside it), `git add -A`, `git add --force .github/x`, `git commit --amend`, `-am`, `--no-verify`. **Fix:** deny `--output` and `--no-index` for diff and log; allow `git add` only with explicit paths (no `-A`, `.`, `--force`); allow `git commit` only as `-m <msg>`; one refused-case test each against the generated rules AND `ToolPolicy`.
3. **PR body** (`publisher.py` / the PR composer): the file list is agent text, unescaped and unlimited. A committed path like ``backend/x` @octocat `.py`` breaks out of the code span and `@mention`s; a path can inject a `[x](https://evil...)` link, carry U+202E, or be 300 characters. The agent *summary* held up. **Fix:** refuse (failed run) any path with characters outside a conservative set (printable ASCII, no backtick, `@`, `[`, `]`, `(`, `)`, `<`, `>`, bidi controls), or render paths in a fenced block with a length cap; tests for each.
4. **Docs overclaim** (`_docs/responder-security-limits.md`): it calls the diff gate "the control that does not depend on the CLI behaving" and says the token reaches only the runner's `git push`. Findings 1a to 1d contradict both. **Fix:** soften both sentences; after the fixes, state exactly what the gate does and does not guarantee, and add the `--output` gap to the documented limits if it is not closed.

Minor, fix if cheap: preflight accepts `loggedIn:false` with exit 0 and `authMethod:claude.ai` (the real CLI exits 1 when logged out); a valid result over 5 MB becomes `output_unparseable`; the CLI output file is not size-capped during the run; a `RESULT:` line inside a code fence counts as the result.

## Process pitfalls learned this session (save time)
- **Push guard:** only `git push -u origin <current branch>` of the main working tree, only `claude/*`. Agents' worktrees cannot push; remove the worktree, check the branch out in the main tree, push.
- **Pre-commit guard:** a commit that touches a protected path (`Makefile`, `AGENTS.md`, `_docs/specs.md`, `_docs/architecture.md`, `.github/`) must contain only protected paths and be made with `HUMAN_APPROVED=1` after the owner approves that exact diff; post an approval record (generate it from git, do not type it). A merge commit cannot pass this, so replay unpushed commits onto a fresh branch from `main` instead of merging `main` in.
- **A merged PR's branch is dead:** pushing more commits to a branch whose PR already merged strands them. Check `git branch -r --no-merged origin/main` and PR state before pushing.
- **Stop-hook noise:** `.claude/worktrees/` shows as untracked while agent worktrees exist; it clears when they are removed. Do not commit it.
- **One command per shell call, no chaining;** use `make issue-comment N=<n> FILE=.scratch/<file>` for long comments and `make issue-dump N=<n>` to read issues; `make clean-scratch` at the end of an issue.
- **Real-mode refusals:** the responder refuses real mode if `CI`, `GITHUB_ACTIONS`, `PYTEST_CURRENT_TEST` or `DEPLOYMENT_ENVIRONMENT=test` is set.
